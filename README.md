# 세종대왕을 알현하라!

한글날 교육용 웹 게임입니다. 태블릿(가장 작은 기기: 아이패드 미니)에서 가로·세로 모두 돌아갑니다.
플레이어는 꿈속에서 조선 1446년의 육조거리에 떨어져, 경복궁의 문 다섯을 자모 조합과 퀴즈로 열고 사정전에서 세종을 알현합니다.

| 저장소 | 학년 | 주소 |
|---|---|---|
| [`sejong-e`](https://github.com/jeongyenolgong/sejong-e) | 초등 | https://jeongyenolgong.github.io/sejong-e/ |
| [`sejong-m`](https://github.com/jeongyenolgong/sejong-m) | 중등 | https://jeongyenolgong.github.io/sejong-m/ |

두 저장소는 **점검 퀴즈·힌트 퀴즈 데이터만 다르고** 나머지(게임 코드 · 자모 조합 · 시나리오 · 그림 · 화면 글자)는 같습니다.
어느 학년인지는 저장소 맨 위의 `grade.json` 하나가 정합니다.

> ⚠️ **공유 부분의 본은 `sejong-e`입니다.** 게임 코드·그림·화면 글자를 고칠 때는 `sejong-e`에서 고치고
> `npm run sync-to-m`으로 `sejong-m`에 복사합니다. `sejong-m`에서 공유 부분을 직접 고치면 다음 복사 때 덮입니다.

---

## 1. 실행하기

필요한 것: [Node.js](https://nodejs.org/) 20 이상.

```bash
npm install        # 처음 한 번
npm run dev        # 엑셀을 굽고 개발 서버를 띄운다 → 터미널에 뜬 주소(http://localhost:5173/)를 연다
npm run build      # 배포용 파일을 dist/에 만든다
npm run preview    # dist/를 띄워 본다
```

같은 와이파이의 태블릿에서 열어 보려면 `npx vite --host`로 띄우고, 터미널에 뜬 `Network:` 주소를 태블릿 브라우저에 넣습니다.

## 2. 만든 재료

- **자바스크립트 · CSS · JSON** 뿐입니다. 화면 틀(React 등)은 쓰지 않습니다.
- [Vite](https://vite.dev/) — 개발 서버와 배포 파일 묶기에만 씁니다.
- [exceljs](https://github.com/exceljs/exceljs) — 엑셀을 JSON으로 구울 때만 씁니다(개발용 · 게임에는 안 실립니다).
- [jsPDF](https://github.com/parallax/jsPDF) — 마지막 [저장]에서 PDF를 만들 때만 불러옵니다. 판은 캔버스에 직접 그려 담습니다(`src/lib/pdf.js`).
- 글꼴 **고운바탕**(SIL OFL) — `src/fonts/`에 실어 보냅니다(학교 망에서 바깥 글꼴이 막혀도 뜹니다). 고운바탕에는 한자가 없어 알림창의 한자(光化門 등)는 기기 글꼴로 나옵니다.
- 서버가 없습니다(깃헙 페이지 정적 배포). 로그인·계정·개인정보가 없고, 진행을 저장하지 않습니다(켤 때마다 캐릭터 선택부터 · 2026-09-23).

## 4. 글을 고치려면 — 엑셀

화면에 뜨는 글은 **모두 엑셀에 있습니다**(하드코딩은 넷뿐 — 조작키 ◀ ▲ ▶ `B-03`, 넘김 ‹ › `B-05`, 서약서 체크 칸 `B-11`, 판 왼쪽 위 「2 / 3」 `B-12`).
튜토리얼 연습 판은 `jamo.xlsx`·`quiz_hint.xlsx`의 「연습」 시트에서 따로 굽습니다(`src/data/practice.json` · 갈무리 판·PDF 11장에 섞이지 않습니다).

1. `content/`의 엑셀을 고친다(열 이름·시트 이름은 바꾸지 않는다).
2. `npm run data` — `src/data/*.json`으로 다시 굽는다(`npm run dev`·`npm run build`는 이것을 먼저 돌린다).

엑셀 안의 「읽는 법」 시트에 열마다의 뜻이 적혀 있습니다. 점검 퀴즈 코드는 **포스터를 인쇄한 뒤에는 바꾸지 않습니다**(포스터와 화면이 어긋납니다).

## 5. 그림을 넣으려면 — 그림마다 설정 파일

**AI로 뽑은 그림(`.webp`) 26장**이 들어가 있습니다(2026-09-26 · 플레이테스트 뒤 다시 그린 판). 그림 목록은 `content/image_list.xlsx`.
그림은 audience 폴더의 `art/`(원본 PNG · 다시 그린 것은 `art/redraw/`)에서 `tools/export_to_game.py`로 내보냅니다 — 어느 파일을 쓰는지(`SRC` 표) · 16:10으로 자르기 · 캐릭터 바탕 빼기와 몸/두 다리 나누기 · 문짝과 「문 너머」 · 시작 화면 구름·학 · 꿈 구름 오리기 · 설정 파일 숫자까지 이 스크립트가 고칩니다. 그다음 `npm run sync-to-m`.
튜토리얼 설명 판의 두 그림(`tut_tablet_e/m` · `tut_poster_e/m`)은 학년마다 한 벌씩입니다 — 포스터는 두 줄이 모두 오답인 장(정답 코드가 새지 않게).
빈 틀 그림(`.svg`)은 아직 지우지 않고 남겨 두었습니다.
그림 하나에 설정 파일 하나(`public/images/<이름>.json`)가 붙어, 그림 안의 위치에 달린 값을 코드 밖에 둡니다.

**진짜 그림이 오면**

1. `public/images/`에 같은 이름으로 넣는다(예: `bg_map_2_gwanghwamun.png`).
2. 그 설정 파일의 `"file"`을 새 파일 이름으로 바꾼다.
3. 그림을 보며 숫자만 고친다. 코드는 건드리지 않는다.

좌표는 모두 **그 그림에 대한 백분율**입니다(x: 왼쪽 0 → 오른쪽 100 · y: 위 0 → 아래 100). 캐릭터 자리는 발끝입니다.

| 설정 | 어디에 | 뜻 |
|---|---|---|
| `walk.minX` · `walk.maxX` | 지도 · 문 앞 · 알현 | 좌우로 걸을 수 있는 범위(그림의 담장·행각이 닿는 곳까지) |
| `walk.bands` `[[y, minX, maxX] …]` | 지도 1·6장 | 높이마다 걷는 폭(육조거리 · 근정전) — 사이는 잇는다 |
| `start` · `stand` | 지도 / 문 앞 · 알현 | 캐릭터가 서서 시작하는 자리 |
| `scale` `[[y, 키] …]` | 지도 | 캐릭터 키가 발 높이를 따라 커지고 작아진다(그림 높이에 대한 %) |
| `charHeight` | 문 앞 · 알현 | 캐릭터 키(그림 높이에 대한 %) |
| `exitY` | 지도 1·6장 | 여기까지 올라가면 다음 장이 위에서 내려온다 |
| `gate` `{x1, x2, y}` · `topY` | 지도 2·3·4·5·7장 | 문(영제교는 다리) 자리 — 이 폭 안에서 y까지 오르면 문 앞 화면 · 그 밖은 topY(없으면 y)에서 선다 |
| `spots[]` | 지도 1·2·3·4·5·7장 | 실마리 곳 — 사람은 발 자리 `{x, y}` · 담장·개울가·대문은 칸 `{x1, x2, y1, y2}` · n번째 실마리 → 곳 n |
| `reach` | 지도 7장 | 곳에 닿는 거리(기본 6 · 곳이 가까워 작게) |
| `practice` | 지도 1장 | 튜토리얼 연습 대문 칸과 ▲가 멈추는 높이(stopY) |
| `officers[]` | 지도 6장(근정전) | 품계석 앞 관리 8명의 발 자리 — 차례 좌1 → 우1 → … → 우4 |
| `audienceY` | 지도 8장(사정전) | 여기 닿으면 알현 화면 |
| `doors.left/right` | 문 앞 넷 | 오려 낸 문짝 그림(`cut_door_*`)과 그 자리 · 경첩은 바깥쪽 세로 변 |
| `beyond` | 문 앞 넷 | 문짝 뒤에 까는 「문 너머」(양옆 칸의 너머를 이어 붙인 것 · `beyond_*`) |
| `doorRange` · `pushY` | 문 앞 넷 | 이 폭 안에서 pushY까지 오르면 문을 민다 |
| `walls[]` · `endY` | 영제교 정면 | 다리 위 투명한 벽 두 지점 · 다 건넌 끝 |
| `stopY` | 알현 | 캐릭터가 멈추고 자막이 시작되는 자리 |
| `clouds[]` · `birds[]` | 시작 화면 | 그림에서 오려 낸 구름 셋 · 학 넷과 한 번 가로지르는 초(학은 `dir` 머리 쪽으로) |
| `clouds.pieces[]` · `clouds.curtain` | 꿈(`bg_dream`) | 제자리에서 둥실거리는 가장자리 구름 · 들어설 때 양옆으로 걷히는 구름 두 장 |
| `parts` | 캐릭터 뒷모습 | 몸 / 왼다리 / 오른다리 세 장과 가랑이 높이(`yc` %) — 걸을 때 다리를 번갈아 든다 |

빈 틀 그림을 다시 만들려면 `npm run placeholders`(이미 있는 설정 파일은 덮지 않습니다).

## 6. 움직임의 초

모든 움직임의 초는 `src/lib/timing.js` 한 곳에 있습니다. 확정된 값(✅)과 정해진 적 없어 개발이 둔 값(📝)이 표시돼 있습니다.

## 7. 배포

`main` 가지에 올리면 깃헙 액션(`.github/workflows/deploy.yml`)이 빌드해 깃헙 페이지에 올립니다(몇 분 걸립니다).
주소가 저장소 이름 아래 하위 경로라서 모든 파일을 **상대 경로**로 부릅니다(`vite.config.js`의 `base: './'`). `/`로 시작하는 경로를 쓰지 마세요.

## 8. 두 저장소 맞추기

```bash
# sejong-e에서 — 공유 부분을 옆 폴더의 sejong-m으로 복사한다(grade.json·.git은 건드리지 않는다)
npm run sync-to-m
```

두 저장소 폴더가 나란히 있어야 합니다(`…/sejong-e`, `…/sejong-m`). 복사한 뒤 `sejong-m`에서 커밋·푸시합니다.

## 9. 기획 문서

게임의 정의는 기획 문서가 원본입니다(이 저장소 밖 `docs/` 폴더로 함께 넘깁니다). 코드 주석의 절 번호(예: 「요소정의 10-1」)가 그 문서의 절입니다.

| 문서 | 무엇을 정하나 |
|---|---|
| `요소정의_v1.md` | 화면·요소·규칙 전부 — 화면 목록(3-1), 지도(0-1), 미니맵(0-3), 문제판(5-2), 알림창(5-3), 자모 조합(6~11), 퀴즈(10-0~10-3), 알현~끝(14-1), 그림 조건(10) |
| `화면텍스트_목록_v1.md` | 화면에 뜨는 모든 글과 번호 — `ui_text.xlsx`의 원본 |
| `퀴즈_점검_v1.md` · `퀴즈_힌트_v1.md` | 퀴즈 문안 — 두 퀴즈 엑셀의 원본 |
| `문제은행_v1.md` | 자모 조합 낱말 열한 개를 뽑은 근거 |
| `세종일화_v1.md` | 힌트 퀴즈 재료가 된 세종 일화와 원문 |
| `궁궐구조_확인.md` | 경복궁 문의 차례와 이름의 근거 |
| `그림목록_v1.xlsx` | 그림 26장 — `image_list.xlsx`의 원본 |
| `HANDOFF.md`(docs 옆) | 결정의 기록 — 무엇을 정했고 무엇을 버렸는지 |

## 10. 기기에서 확인할 것 🧪

- 화면 자판: 음절 칸을 누르면 올라오는지 · 판이 자판 위로 밀려 올라가는지 · 천지인 자판으로도 들어가는지
- 점검 퀴즈의 숫자 칸이 숫자 자판을 부르는지(아이패드는 글자 자판 크기로 올라올 수 있다)
- 한지 넘김 · 문짝 돌아감이 매끄러운지
- 세로로 들었을 때의 배치 · 화면이 캐릭터를 따라 옆으로 밀리는지 · 손가락으로 그림을 밀 수 있는지
- 프롤로그에서 화면 아무 데나 눌러 넘어가는지
